04 — Method

Four passes, in order, every time.

The order matters: each pass produces the input the next one needs.

  1. 01

    Sit with the operator

    Requirement sessions with POs and PMs, then time with whoever actually uses the thing. I leave with the vocabulary they use, not the vocabulary the system uses.

    Output — problem statement, current-state flow

  2. 02

    Draw the structure

    Information architecture and user flows before any pixels. If the structure is wrong, no amount of visual polish will save the screen.

    Output — site map, flows, wireframes

  3. 03

    Build from tokens

    High-fidelity UI assembled from the design system, not drawn fresh each time. Variables and tokens mean a change lands everywhere at once.

    Output — component-based hi-fi, prototype

  4. 04

    Test, then spec

    Usability testing with real users, then a handover written for engineers — states, edge cases, behaviour under load. I stay in review until it ships.

    Output — findings, dev-ready spec
